Retail Demand Forecasting & Inventory Risk Analytics

Author: Aarush TyagiRole: Data Science Intern — Zidio Development

Project Overview

This project builds an end-to-end retail demand forecasting and inventory-risk analytics system using real retail inventory data.

The objective is to forecast future product demand, evaluate the forecast against a simple baseline, identify stockout and overstock risks, and convert model outputs into practical inventory-planning decisions.

Business Objectives

Forecast product demand using historical and engineered features.

Apply leakage-safe time-series feature engineering.

Use chronological train, validation, and test splits.

Evaluate a machine-learning forecasting model against a simple baseline.

Perform rolling-origin / walk-forward backtesting.

Score stockout and overstock risk.

Generate inventory decisions such as:

ORDER NOW

REORDER SOON

MONITOR

HOLD

MARKDOWN

REDUCE INVENTORY

Estimate potential inventory exposure in INR where the available data supports it.

Export results that can later support a dashboard or scoring service.

Forecasting Models

Baseline

A simple last-value / naive forecast is used as the baseline.

Machine Learning Model

The primary CPU-friendly machine-learning model is:

HistGradientBoostingRegressor

A small hyperparameter search is performed to keep the project practical for local execution.

Evaluation Metrics

The project evaluates forecasts using:

MAE — Mean Absolute Error

RMSE — Root Mean Squared Error

WAPE — Weighted Absolute Percentage Error

sMAPE — Symmetric Mean Absolute Percentage Error

The ML model is not automatically considered better. It is selected only when its performance provides evidence of improvement over the baseline.

Time-Series Validation

Random train-test splitting is intentionally avoided.

The project uses:

Chronological train split

Chronological validation split

Chronological test split

Rolling-origin / walk-forward backtesting

This prevents future observations from influencing earlier forecasting decisions.

Limitations

Potential limitations include:

Missing supplier lead-time information

Missing promotion/calendar information

Missing supplier constraints

Forecast uncertainty

Risk thresholds requiring business calibration

Financial estimates depending on available price and inventory data

The results should therefore be treated as analytical decision support rather than an autonomous inventory-management system.
